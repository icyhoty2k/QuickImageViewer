They are frequently paired in C++ development, such as in your QuickImageViewer project, because they provide a highly efficient, cross-platform workflow. The Roles Feature CMake (The Architect) Ninja (The Construction Crew) Primary Goal Generate build configuration files. Execute the build process. Input CMakeLists.txt (Human-readable logic). build.ninja (Machine-generated instructions). Nature Meta-build system. It doesn't compile your C++ code directly. Low-level build system. It calls the compiler/linker directly. Key Strength Handles cross-platform abstraction and dependency discovery. Designed for extreme speed and parallel execution. How They Connect The connection is a sequential workflow where CMake produces the precise "blueprint" that Ninja follows. Configuration Phase: You run CMake. It reads your CMakeLists.txt files, analyzes your system environment (compilers, libraries, include paths), and determines exactly what needs to be built. Generation Phase: Instead of generating old-fashioned Makefiles, CMake generates a build.ninja file. This file contains the exact sequence of commands and dependency relationships required for Ninja to succeed. Execution Phase: You run the Ninja command. Ninja reads its generated build.ninja file and executes the actual compilation and linking commands (invoking your C++ compiler, like MSVC or GCC). Why They Are a Powerful Combination Speed: Ninja is intentionally minimal. It is optimized to be as fast as possible, often rebuilding faster than traditional Make-based systems. It handles dependencies and parallel task execution very efficiently. Modernization: Using CMake with Ninja is the industry standard for modern C++ development. It keeps your build logic (in CMakeLists.txt) clean and platform-independent, while offloading the heavy lifting of process management to Ninja. IDE Integration: Since you work with IntelliJ IDEA, you likely notice that the IDE treats CMake as the source of truth. When you open a project, IntelliJ (via the CLion plugin or similar C++ tools) calls CMake to generate the Ninja files, and then uses Ninja to provide real-time feedback on errors and build status. Typical Workflow In your terminal or build process, the interaction looks like this: Configure: cmake -G Ninja -S . -B build This tells CMake to use the Ninja generator. Build: cmake --build build This invokes the underlying build tool (Ninja) automatically. Because Ninja is focused solely on executing the build commands quickly, it does not need to handle complex logic—it just needs the "marching orders" that CMake provides. is it optimized in clion because i use clion 2026.1 Yes, the combination of CMake and Ninja is considered highly optimized in CLion 2026.1. Why QuickImageViewer?

Built for Speed

Unlike modern web-based electron wrappers, qIV is a pure native application. It uses a GPU bitmap cache to keep decoded images in VRAM, preloading in both directions on a background thread. The UI thread never blocks.

Hardware Accelerated

Built directly on top of Direct2D and the Windows Imaging Component (WIC). It achieves zero-flicker rendering and instantly falls back to GDI software rendering only when necessary.

Format Support

Native OS formats are handled by the zero-dependency Windows Imaging Component, while complex formats utilize highly optimized custom and static library decoders.

Core Features

Navigation & UI

  • Instant Startup: Hide to tray with Esc and recall instantly, process stays resident in RAM.
  • Thumbnail Strips: Scrollable, wrap-around thumbnail previews for cache, directory, and history.
  • Smart Navigation: Smart jump between first/last images, instant folder history toggling, and Find mode with wildcard support.
  • Overlay System: 9 independently configurable data slots rendered directly on the canvas.

Offline Reverse Geocoding

GPS coordinates in EXIF data are resolved to full location details (City, State, Country, Timezone) with zero network calls. A compressed zlib database of GeoNames data is embedded directly into the executable.

GPU Color Effects

Real-time, non-destructive image adjustments via the Direct2D effect graph. Bake and save directly to disk with Ctrl+S.

Command-Line & Kiosk Mode

qIV supports extensive CLI arguments for automation, slideshows, and locked-down kiosk environments.

QuickImageViewer.exe -dedicated -lock -fullscreen -slideshow -shuffle -slideshowInterval 8 -startFolder "D:\Ads"

Runs an isolated instance on a dedicated monitor, loops a shuffled slideshow every 8 seconds, and ignores all user mouse/keyboard input.

Architecture & Building

Written in C++23. Requires CMake and MSVC (Visual Studio 2022 or CLion). The threading model utilizes atomic indices and WM_QIV_REPAINT messages to synchronize the worker thread pool back to the UI thread seamlessly.

cd QuickImageViewer
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . --config Release
