3. Asynchronous Decoding Threads
If you are worried that other formats are "slow," the hardware-level solution is to increase the parallelism in your Decode Thread architecture.

The Multi-Threaded approach: Since you have a 16-core (or higher) CPU, don't just have one "Decode Thread." Create a small, fixed-size Worker Pool.

Implementation: When your prefetcher triggers (the current ± 3), it shouldn't just send a job to one thread. It should fire off all 5-7 images to the thread pool simultaneously.

The "Massive" Gain: Even if a PNG takes longer to decode than a JPEG, if you decode 5 images in parallel, your UI will never feel the "slow" format because the next image is almost certainly already sitting in RAM before the user even thinks about scrolling.

Summary Strategy
If you want to move away from format-specific optimizations:

Stop using IWICFormatConverter for everything. Use CopyPixels into a pre-allocated buffer and handle the final pixel layout (swizzling to BGRA) yourself using DirectXMath (SIMD).

Implement a Thread Pool for your decoder. This will make your application speed scale linearly with the number of cores on your 14900KF/9950X, regardless of the file format.

By doing this, you are effectively "turbo-charging" your entire pipeline rather than just creating a fast-lane for JPEGs.
